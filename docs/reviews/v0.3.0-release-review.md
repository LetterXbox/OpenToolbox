## Rounds 2 to 4

- **Round 2** (`452201c`): new findings were fixed in `55230dd`.
  - A PDF test expected the wrong error.
  - The owner-only removal wording didn't match the behaviour.
  - Save As failed silently, so it was replaced by **Show in Finder**.
  - Trim Audio rounded the times it shows.
  - Transcribe could start without a supported language.
  - Narration comments were left in the code.
- **Round 3** (`55230dd`): Unsaved Recordings could have listed or deleted a folder put there by hand. It now lists only regular files, per tool. The other findings were fixed in `807f001`:
  - the wrong tool folder was used when saving a kept recording;
  - recorders didn't refresh their lists;
  - save and discard errors were hidden;
  - Trim Audio rounded a time when Return was pressed;
  - section banners were left in the code.
- **Escalation, after round 3:** Fable raised two more recording paths, fixed in `0078095`: a stop that macOS starts itself, and quitting during a recording.
- **Round 4** (`0078095`): it confirmed the escalation. Its new findings were fixed in `2939e27`:
  - Unsaved Recordings works in folders opened without following links, checks file identity, and removes only single files.
  - Recording callbacks are tied to their session.
  - Encoder errors keep the earlier message, and recovery errors stay visible.
  - Not applicable: recordings kept in an earlier store layout. No build with that layout was distributed.
- **Round 5** (`2939e27`): resolved the linked folder, the encoder message and the hidden error.
  - The 30-second fallback could treat a recording macOS was still writing as finished. Fixed: a recording stays active until macOS reports it finished or failed, and quitting is refused until then.
  - The partial save could hide a delayed write error. Fixed.
  - Listing re-resolved the folder path. Fixed: it reads the opened folder.
  - A file swapped in between the identity check and the action was escalated (item C in `resolver-recording-recovery.md`). The read side is fixed in `e5c4c5d`, and the unlink gap is deferred.
- **Round 6** (`e5c4c5d`): it confirmed escalation C and resolved the round-5 fixes. It found that the "still finishing" message could stay after a successful save. Fixed: the message is shown only while the recording is finishing.

- **Round 7** (`fe3ddc2`): it passed `fdeb3d2`, which keeps hidden tools at their last size while the sidebar opens or closes and moves Quick Open to the toolbar. That review read the source only: keyboard focus, VoiceOver and unusual window sizes weren't run. Merging main brought back the v0.2.0 README, which named Xcode 16, left out the recording recovery steps and the new network uses, and listed the old tools. Fixed in `14c81f3`, a README rewritten for v0.3.0.

- **Round 8** (`14c81f3`): it confirmed the round-7 README fixes and found six wording problems, five in text carried over from v0.2.0. The README said originals are never changed, though Batch Rename can rename in place, Find Duplicates moves copies to the Trash and Quarantine Helper clears a file's flag. It left update downloads out of the network list, sent readers to Engine Manager to turn tools on or off, and called the planned video tools "Coming soon". It also said older Macs offer fewer transcription languages. And Trim Audio, in the app as well as the README, called CAF lossless although a CAF can hold compressed audio. The app wording is fixed in `f5d0512`, and the README in the next commit.

- **Round 9** (`e77339a`): it confirmed all round-8 fixes, and found that the Trim Audio change renames code and rewords text only. It found that the deferred entries described future work, which public records leave out, and that the README made automatic updates sound like they install right after the daily check. Both are fixed in the next commit.

- **Round 10** (`885c8cc`): it confirmed both round-9 fixes and found nothing new.

- **Round 11** (`1440ce5`): testing found that the first Transcribe on a Mac that hadn't yet answered the Speech Recognition prompt crashed. macOS delivered the answer on a background queue to a callback that required the main thread. Fixed in `1440ce5`: the callback no longer requires the main thread, and a test delivers the answer from a background queue. The round passed that fix; `f4ba120` then fixed the test's build on the newer Swift compiler. The round also found that Scan Document's drag-and-drop import had the same kind of callback, and that dropping a PDF or an image could crash it. Fixed in `d3e7f30`: the files are now read off the main thread and the pages are handed back to it.

- **Round 12** (`d3e7f30`): it confirmed the Scan Document fix and found nothing new.

- **Round 13** (`e98389f`): the owner added an opt-in test channel to v0.3.0, **Include test builds**, which offers GitHub pre-releases. The round reviewed that change and found eight problems, all fixed in `875850f`:
  - Two errors stopped the build: a missing import, and an initializer that read a property before every property was set. The import was already restored in `8f94897`.
  - Changing the option during a check recorded the old channel's answer. The check now runs again on the new channel.
  - The publishing steps could tag the wrong commit. They now pass `--target`.
  - No test turned the option off while an update was in progress. The update state can now be tested, and tests cover turning the option off while a test build is offered, downloading or staged, and that a staged full release still installs.
  - On a test build, the "up to date" message could call it the latest test build after a stable-only check.
  - The packaging script accepted version numbers the app can't read.
  - A comment described an internal setting.


## Deferred

- **Kept-file removal:** a different regular file swapped into Unsaved Recordings during the microseconds between the identity check and the unlink could be removed. Astra allows this past v0.3.0.

- **Recording recovery when both saves fail:** if both the output folder and Unsaved Recordings refuse a recording, it stays at the temporary path shown in the error. Astra allows this past v0.3.0, and it's listed in the README.
