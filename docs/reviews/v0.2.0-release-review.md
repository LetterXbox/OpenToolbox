# Release review: v0.2.0 (app experience, Watermark, Disk Speed Test)

**Reviewer:** GPT-6.2 Astra, high effort, read-only, on `63ec128` (`v0.1.2..63ec128`).

## Round 1

Three blockers, ten should-fixes and two nits. The changes are in `bc2bd71`; the round 2 re-check below found several of them only partly fixed.

| # | Severity | Finding | Outcome |
| --- | --- | --- | --- |
| 1 | Blocker | Two Disk Speed Tests could each pass the free-space check and together fill the disk. Unknown free space was accepted, and the figure used could include purgeable space. | Fixed. Only one test runs at a time in the app. Free space must be known and is read with `statfs`, so purgeable space doesn't count. It is checked again every eight blocks while writing, and the test stops before it would eat into the 1 GB reserve. Tests: `onlyOneTestRunsAtATime`, `stopsWhenTheReserveWouldBeUsed`, `refusesWhenTheVolumeIsTooFull`. |
| 2 | Blocker | The test wrote even if unlinking its file failed, which could leave a hidden test file behind. | Fixed. Writing starts only after the unlink succeeds. Otherwise the test stops and names the file's path so it can be deleted. |
| 3 | Blocker | A watermarked PDF was written with only a media box, so content the source's crop box hid became visible. | Fixed. Each page keeps its crop box, mapped through the page's rotation, and the watermark is laid out in that visible area. Tests: `cropBoxesFollowThePageRotation`, `pdfCopiesKeepTheCropBox`. |
| 4 | Should-fix | The chosen volume was identified only by its path, so another drive mounted at the same path would be tested instead. | Fixed. The volume's UUID is recorded when the list is read and must still match. After the test file is created, its device must equal the folder's device. Test: `refusesADifferentVolumeThanTheOneChosen`. |
| 5 | Should-fix | The result of turning off the file cache was ignored, so a read could be served from memory. | Fixed. If `F_NOCACHE` fails, the test stops and says that the volume can't be measured uncached. |
| 6 | Should-fix | With no window open in menu bar mode, an update prompt from an automatic check was lost. | Fixed. The request stays pending until a window or the menu bar icon opens the Software Update window. The menu also lists an available update. |
| 7 | Should-fix | Tapping a notification opened the tool in whichever window was in front, not the one the work ran in. | Fixed. The notification carries the window's identifier. If that window is still open it is brought forward; otherwise the tool opens in the front window. |
| 8 | Should-fix | Batch Rename's shared session made every window that had opened it show the spinner, dot and notification. Its shared undo journal let any window undo another's rename. | Reporting is fixed: only the window that started a rename or undo reports it. Undo is deferred, see below. |
| 9 | Should-fix | The activation policy ignored Settings and Software Update windows, so OpenToolbox could leave the Dock while one was open. | Fixed. Any visible titled window other than a panel keeps OpenToolbox in the Dock. The policy is updated whenever a window becomes key or closes. |
| 10 | Should-fix | Watermark silently kept only the first frame of animated GIFs and multipage TIFFs. | Fixed. Images with several frames are refused with an explanation. Test: `multiFrameImagesAreRefused`. |
| 11 | Should-fix | A positioned watermark could run off the page, especially when diagonal. | Fixed. A positioned mark is scaled down until it fits inside the margins, including its footprint when turned. Test: `positionedMarksStayInsideTheMargins`. |
| 12 | Should-fix | The README said closing a window stops all of its work, but batch file jobs finish. | Fixed. The README now names the jobs that stop and says file batches already under way finish. |
| 13 | Should-fix | A new window always opened JSON Formatter, even when it was disabled. | Fixed. A disabled initial tool falls back to the Tool Catalog. The menu bar, Quick Open hotkey and notifications never open a disabled tool. |
| 14 | Nit | The finished dot and the notification used different rules for "out of sight". | Fixed. Both use the same rule, and the dot clears when its window comes to the front showing that tool. |
| 15 | Nit | Section banner comments violated the comment rule. | Fixed. Removed. |

## Round 2

The re-check at `401d51d` marked 2, 5, 6, 7, 9, 11, 13, 14 and 15 resolved (6 and 9 still to be confirmed on macOS). It accepted deferring the shared undo journal if the undo control says which rename it will undo. The changes below are in the next commit.

| Item | Re-check said | Change |
| --- | --- | --- |
| 1 (partial, blocker) | The check while writing skipped a failed reading, and a short write could step past the check interval. | The checks read the open test file's volume with `fstatfs`. A reading that fails stops the test. The next check is scheduled by bytes written, not by exact block boundaries. Tests: `stopsWritingWhenFreeSpaceDropsIntoTheReserve`, `stopsWritingWhenFreeSpaceCannotBeRead`. Both pass the first check, then get a low or failed reading partway through. They check that writing stops halfway, no reading starts, and nothing is left behind. |
| 3 (partial, blocker) | A crop box disjoint from the media box fell back to the whole page. | A page whose crop box doesn't overlap its media box, or is empty, is refused with an error naming the page. Test: `aCropBoxOutsideThePageIsRefused`. |
| 4 (partial) | A missing UUID disabled the check, and a remount between the path lookups could pass. | The volume list records each volume's file system ID (`f_fsid`) and leaves out any volume without one. The test opens the folder once and checks that descriptor's file system ID. It then creates and unlinks the test file relative to that descriptor. The read-only check also uses the descriptor. Test: `refusesADifferentFileSystemThanTheOneChosen`. |
| 8 (partial) | The inline spinner still showed in every window. | The spinner shows only in the window doing the work. Under the undo button, Batch Rename says that undo restores the last rename made in any window, and names the number of files and their folder. |
| 10 (partial) | A multipage TIFF chosen as the watermark artwork silently used its first page. | Artwork with several frames is refused too. Test: `multiFrameArtworkIsRefused`. |
| 12 (partial) | With the menu bar icon off, closing the last window quits the app, so batches don't finish. | The README now says batches finish as long as OpenToolbox keeps running, and that closing the last window quits it when the menu bar icon is off. |
| New (should-fix) | Diagonal tiles used the turned footprint for spacing, leaving long text with one row. | Tiles keep the plain mark size for spacing; only positioned marks use the footprint. Test: `diagonalTilesStillCoverThePage`. |
| New (should-fix) | The reserve test could pass without writing. | Replaced by the two tests under item 1, which use controlled space readings. |
| New (nit) | Narration comments on internal helpers. | Removed. |
| New (nit) | This record overstated verification. | Outcomes are now stated per round, and the build and test results are recorded below once they have run on macOS. |

## Deferred

- **Finding 8, shared Batch Rename undo.** The undo journal is app-wide on purpose. It holds the last rename made anywhere in OpenToolbox, and undoing it from any window restores the same files. Batch Rename says so under the undo button and names the files' count and folder. Files are never renamed twice, because the app-wide lock still allows one rename or undo at a time.
